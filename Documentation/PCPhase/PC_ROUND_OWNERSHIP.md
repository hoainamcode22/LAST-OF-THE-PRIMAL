## Rules for this phase
- **Prehistoric only (owner):** every model, material, prop, icon and sound must belong to a prehistoric dinosaur world.
  Human gear is primitive (wood, stone, fiber, leaves, hide, bone, rope, shipwreck scraps). No modern shapes.
- **PC first:** quality over mobile constraints; keep LOD / culling / instancing / shared materials / pooling.
- **Testing policy (owner):** no full-suite runs. After each of your major steps: cloud compile (`./cc.sh all`), PC compile
  after deploy (no `error CS`), Console check (no errors / exceptions / missing references in the editor log after your
  builders run), asset import check (no import errors). Run a targeted PlayMode test only when a change cannot be checked
  any other way. The Lead runs one technical pass at the end; the owner plays by hand.
- **Scene edits** only through your own idempotent builder (bridge-callable, logs, saves the scene), each under its own
  root; snap to the terrain at build time. After ENV changes the terrain, RES / AI / STORY / WORLD re-run their builders.
- **Blender:** use background Blender (`mcp__remote-devices__Blender__execute_blender_code_for_cli` or the interactive
  session only for a scene you created and remove). Never save over a file the owner has open; work on copies; dated backups.
- Shared append-only files: `Core/GameEvents.cs` (GameEventType), `Audio/SfxPlayer.cs` (SfxId enum: append ids only, the
  rest of the file is U's), `VFX/VfxPool.cs` (VfxId enum: append only). Re-read right before editing, append at the end.
- Requests for another agent's file go in your report and to the Lead (SendMessage "main" if it blocks you).

## Interfaces
- **Locations (ENV -> all):** `Markers/Zones/<id>` empties + ZoneManager zones (WORLD owns ZoneManager code, ENV provides the markers). Ids: `beach`, `shipwreck`, `forest`, `deep_forest`, `river`, `waterfall`, `meadow`, `canyon`, `wetland`, `cave`, `ridge`, `volcano`, `predator_territory`, `herbivore_valley`, `old_camp`, `fossil_bed`, `nest`, `migration_view` (high-ground viewpoint over the migration route). ENV writes `Documentation/PCPhase/LOCATIONS.md` (id, position, radius, what is there) as soon as the terrain pass is done and tells the Lead.
- **Migration route (ENV + AI):** ENV leaves `Markers/Migration/Route_00..NN` along walkable valley ground (meadow -> river crossing -> near the waterfall -> grassland -> resting area); AI moves herds along it.
- **Day phases (WORLD):** `TimeManager.Phase` enum (Dawn, Morning, Noon, Afternoon, Dusk, Night) + `GameEventType.DayPhaseChanged`. AI, STORY and audio read it.
- **Wetness (WORLD -> ENV / U):** `WeatherManager` drives the global `_PF_Wetness` (0..1, with drying lag); ENV's shaders and the player cloth read it.
- **Hazard zones (WORLD):** `HazardZone` (heat, smoke) near the volcano; SurvivalEnvironment adds heat; HUD warning via an event (`GameEventType.HazardWarning`), SURV's HUD shows it (request).
- **Missions (STORY):** listens to `GameEvents` (ZoneEntered with the location ids, Drank, FireLit, FoodCooked, StructurePlaced, Slept, CreatureSighted, herd / migration / track events from AI). AI appends `HerdSighted`, `MigrationStarted`, `MigrationSeen`, `TracksFound` to GameEvents.
- **Dino clips (DINO -> AI):** DINO publishes the state / parameter / trigger names per species in `Documentation/PCPhase/DINO_CLIPS.md`; AI drives them from `DinoLife` / `DinosaurController`. Until then AI uses existing states.
- **Player clips (CHAR -> U):** staging FBX + `clips_manifest.json` in `E:\Model game khủng long\export\staging\` (names, frames, loop, events); U imports and wires.
- **Building shelter (BUILD -> SURV / WORLD):** an enclosure of built pieces counts for `Shelter.Covers` and `SurvivalEnvironment.ShelteredAt`, `Campfire.Sheltered`, rest / save / respawn with a bedroll inside.
- **Death (STORY):** respawn at the last rested bedroll / shelter, lose a share of carried items (dropped as a recoverable bundle where the player died), keep journal / recipes / world.
